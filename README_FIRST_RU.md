# HiChord Pocket — Этап A (проверенная и исправленная копия исходников)

**Внимание:** это **исходники**, а НЕ готовый APK. Компиляция Android-проекта в этой среде не выполнена: здесь нет Android SDK/NDK, установленного Gradle 8.6 и реального устройства с Android. Успешность сборки и звук необходимо проверить через GitHub Actions и на телефоне.

## Что внутри

- Исходники из присланного `make_hichord_zip.py` (19 файлов, с C++ Oboe DSP, JNI, Kotlin и Compose UI).
- Исправления обработки касаний и экранных режимов (см. ниже).
- `.github/workflows/build-apk.yml`, запускающий сборку через установленный в CI Gradle 8.6.

## Как собрать на GitHub (проще, если нет Android Studio)

1. Распакуй ZIP. **В корень репозитория GitHub нужно загрузить содержимое папки `HiChordPocket/`**, а не сам ZIP и не папку как дополнительный уровень.
2. Репозиторий можно сделать **Private**. После загрузки файлов открой **Actions** и запусти `Build HiChord Pocket APK` с помощью **Run workflow** (или дождись запуска после push).
3. Если сборка завершилась успешно, скачай **Artifact** `HiChordPocket-StageA-debug-apk`. Внутри будет `app-debug.apk`.
4. Установи APK на телефон, разрешив установку из выбранного источника в настройках Android.
5. Если workflow упал, сохрани текст шага **Build Debug APK (Kotlin + C++ Oboe DSP)**. Для дальнейшей диагностики нужен именно лог ошибки.

**Технический нюанс:** в архиве **нет** бинарного `gradle/wrapper/gradle-wrapper.jar`: исходный генератор скачивает его из GitHub, а здесь загрузка не удалась. Поэтому локальная команда `./gradlew assembleDebug` требует предварительно добавить официальный wrapper JAR. Но GitHub Actions workflow использует отдельную команду `gradle assembleDebug` после `setup-gradle`, поэтому wrapper JAR для CI не нужен.

## Что исправлено по сравнению с кодом Gemini

1. В `ClassicHiChordScreen.kt` координаты касаний переводятся в систему координат, в которой хранятся прямоугольники кнопок/джойстика.
2. Клавиши настройки KEY/SOUND/MODE теперь не запускают ноты сами по себе; отпускание клавиши настройки не выключает чужую удерживаемую ноту.
3. При управлении джойстиком в меню не происходит лишнего перезапуска аккорда.
4. Кеш превью аккордов пересчитывается при изменении октавы и режима voice leading.
5. При уходе приложения в фон останавливаются ARP/STRUM-корутины, очищается состояние нажатых клавиш.
6. Добавлена индикация ошибки старта нативного аудиодвижка и явный C++ include `<memory>`.

## Проверки, которые выполнены

- Python AST успешно разобрал предоставленный генератор и извлёк **19 файлов**.
- `MusicTheoryEngine.kt` скомпилирован установленным `kotlinc` и пройден тест **9 072 комбинаций** (12 тональностей × 4 лада × 7 ступеней × 3 режима джойстика × 9 направлений), ноты в разрешённом диапазоне.
- AndroidManifest.xml разобран XML-парсером без ошибок.
- `native-lib.cpp` и `SynthEngine.h` прошли C++17 синтаксическую проверку с **заглушкой Oboe**. Это **не** проверка настоящей зависимости Oboe 1.8.1 / Android NDK.

## Что ещё может потребовать исправления после первой сборки

- Настоящие Gradle/Compose/Oboe/NDK зависимости не проверены в работающем Android build.
- Аудиоколбэк возвращает тишину, если `try_to_lock` не получает mutex; при одновременных касаниях возможны краткие выпадения звука — для профессиональной версии лучше применить lock-free event queue.
- Результат `getLatencyMillis()` (или запасной расчёт через `framesPerBurst`) не равен гарантированной полной задержке «палец → звук». Измерение на конкретном телефоне и с проводными наушниками остаётся обязательным.
- Перезапуск аудиопотока при отключении наушников требует практического теста на устройстве.
